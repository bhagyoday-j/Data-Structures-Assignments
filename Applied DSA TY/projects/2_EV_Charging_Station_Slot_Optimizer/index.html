            Algorithm Explanation

            Everything you need for the DSA viva

            What is a Greedy Algorithm?

            A greedy algorithm makes the locally best choice at every step and never reconsiders it, hoping the sequence of local choices produces a globally good solution. It trades guaranteed optimality for speed and simplicity — O(N log N) instead of the exponential search an exact optimiser would need.

            Why is Greedy suitable here?

            Every EV wants the same scarce resource. There is no way to know future arrivals, and evaluating every possible schedule is combinatorially explosive. Greedy lets the station decide in milliseconds, and every decision is explainable: “EV-007 was picked because its priority score of 91.85 was the highest feasible one.”

            The Greedy Choice

            “At every iteration, allocate a charging slot to the highest-priority EV that can feasibly be charged right now.”

            Local optimal choice: the top-ranked EV that still fits in a free slot and inside the remaining power budget.

            Greedy property: once a slot is given, the decision is final — we never shuffle it out for a lower-scoring EV later in the same pass.

            Feasibility & Constraints

            • Slot constraint — a free charging bay must exist.
            • Power constraint — requiredPower ≤ availablePower.
            • Deadline constraint — currentTime + chargingTime ≤ departureTime for a full charge.
            • Priority tier — deadline-satisfiable EVs are placed first; at-risk EVs only consume leftover capacity (a partial charge beats an empty slot).

            Greedy Rule — in one sentence

            The algorithm always selects the currently highest-priority EV that can be feasibly charged.

            Priority Score (weighted, every component normalised to 0–100)

            Priority Score =
    (Urgency Score        × 0.30)   // charging time vs. time left before departure
  + (Low Battery Score    × 0.25)   // 100 - battery%
  + (Deadline Score       × 0.20)   // min-max normalised departure time
  + (Distance Score       × 0.15)   // min-max normalised remaining distance
  + (Vehicle Priority     × 0.10)   // Emergency 100 / VIP 70 / Normal 40

            Worked example — why EV-007 was chosen first

            EV-007 :  Urgency 95 | Battery 90 | Deadline 88 | Distance 75 | Priority 100
   95×0.30 + 90×0.25 + 88×0.20 + 75×0.15 + 100×0.10
 = 28.50 + 22.50 + 17.60 + 11.25 + 10.00
 = 91.85   ← highest score in the fleet, and feasible → allocated to Slot 1

            Honest limitation: Greedy does not necessarily guarantee a globally optimal schedule for every possible charging scenario. It is used here because the objective is to make fast, explainable priority-based scheduling decisions — and because the priority score itself encodes the business rules an optimal solver would need to search for.

            Complexity Analysis

            N = number of EVs at the station
            Time and space complexity of each stage of the greedy scheduler
            Stage Function Time Why
            Priority calculation calculatePriorityScore(ev) + fleet context pass O(N) Two linear passes: one to find the min/max context, one to score every EV with O(1) work each.
            Sorting sortVehiclesByPriority(vehicles) O(N log N) Comparison sort. Every comparison costs O(1) (the score is precomputed), so N log N comparisons.
            Greedy allocation greedySchedule(vehicles, config) O(N) A single pass over the sorted list. Each EV is inspected once, then moved into exactly one of selected / waiting / deferred.
            Trace & metrics buildTrace(), computeMetrics() O(N) One linear pass that emits the teaching log and the comparison statistics.
            Overall runOptimization() O(N log N) Sorting dominates: O(N) + O(N log N) + O(N) = O(N log N).
            Space scored records + trace O(N) Two arrays of length N (scored vehicles, trace steps); no recursion, so no extra stack.
